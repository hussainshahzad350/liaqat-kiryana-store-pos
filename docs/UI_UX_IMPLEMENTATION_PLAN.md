# UI/UX redesign implementation plan

Approved direction: a compact desktop workspace with readable English/Urdu text, neutral surfaces, aligned sections and green reserved for primary actions and selection. Business behavior remains protected by [UI_UX_FREEZE.md](UI_UX_FREEZE.md). The audit is the before-state evidence; its hashes are historical, not a prohibition on authorized presentation changes.

## Design rules

- Space scale: 4/8/12/16/24 px. Use 16 px workspace gutters and 8 px between related controls. Avoid stacked decorative cards.
- Shell: quiet 56 px header; 224 px expanded navigation, 64 px rail below 1200 px client width. Automatic rail sizing must not overwrite the user's stored expansion choice.
- Typography: retain Roboto and NooriNastaleeq. Preserve 1.2 compact line height; measure Urdu in actual controls before adopting smaller type. Never shrink financial amounts to conceal clipping.
- Surfaces: neutral workspace background, distinct neutral panels, thin dividers; elevation only where it explains an overlay. Keep current color/theme preferences.
- Controls: retain visible focus, existing shortcuts and accessible labels. Allow wrapping at constrained pane widths and enlarged text; preserve numeric direction.
- Navigation: keep every existing route and action; show the current section consistently. Make Cash Ledger directly discoverable.

## Implementation phases

| Phase | Deliverables | Acceptance |
| --- | --- | --- |
| 1 — Foundation and shell | Neutral shared surface roles; compact responsive sidebar; quieter aligned header; active Product section and discoverable Cash Ledger; bilingual shell checks. | Small-window rail preserves expansion preference; navigation callbacks/routes retained; shell has no overflow in both languages/themes; contrast roles and regression suite pass. |
| 2 — Sales and Purchase | Shared gutters; available-width product/cart allocation; secondary collapsible recent sales; compact bill metadata and item rows. | Search, bill and checkout visible at minimum client size; long names/amounts readable; existing keyboard and posting workflows pass. |
| 3 — Records and stock | Compact Accounts summaries and flat rows; responsive ledger filters; inventory given primary height; full financial summaries; Items/Categories/Units/Cash alignment. | Fix UX-01/02/03/05; at least double current visible account records at matched wide size; existing history/filter/edit actions reachable. |
| 4 — Dialogs, feedback and settings | Consistent modal anatomy/actions; accurate localized labels; validation presentation using existing rules; semantic feedback; compact settings navigation and bounded forms. | Both languages, minimum windows, long values and error states checked; placeholder actions accurately described; security/backup/receipt behavior preserved. |
| 5 — Final acceptance | Matched before/after screenshots; keyboard and enlarged-text checks; contrast measurements; remove remaining presentation inconsistencies. | No layout overflow or financial truncation in supported variants; full regression and native desktop workflows pass; normal Windows build restored. |

## Verification and evidence

During iteration use focused widget/layout checks and analyzer. Run the full VM regression suite at each phase end, with native workflows relevant to that phase. Use disposable databases only. Native audit harnesses are evidence collectors and may record known defects rather than fail; do not treat a capture pass as proof of a clean layout. Restore the normal `lib/main.dart` Windows build after native tests.

Phase completion records must identify changed presentation files, tests, remaining findings and any limitations. Preserve all existing user work; no schema, repository, money, stock, authentication policy or business-state changes are part of this plan.
